# Оценка качества

Эталон в `truth.json` подготовлен до просмотра результатов модели. Это черновая разметка выбранных правил и сценариев. Для итоговой оценки два независимых рецензента проверяют полноту эталона, включая тяжесть дефектов, и фиксируют согласованную версию до запуска. Официальные Markdown и PDF содержат один смысловой пример. Отчёт по каждому формату считается отдельно. Всего в наборе четыре смысловых примера.

```powershell
python -m eval_samples.prepare --out output/eval
python -m eval_samples.evaluate output/eval/official.md output/official.json
python -m eval_samples.evaluate output/eval/official.pdf output/pdf.json --review output/pdf-review.json
```

Подготовка сверяет байты Markdown с фиксированным SHA-256 организатора. Для автономного запуска добавьте `--official docs/requirements.md`. Скрипт также создаёт читаемый PDF, смешанный PDF с растровой страницей, пустой Markdown, повреждённый PDF и неподдерживаемый TXT. Для последних трёх ожидается диагностическая ошибка до обращения к модели. Смешанный ввод и прерывание запроса к провайдеру требуют явного неполного покрытия и исключают GO. Для отказов транспорта запустите `python -m pytest -q tests/unit/test_provider_runtime.py`. Эти проверки не входят в знаменатели семантических метрик.

Оценщик принимает JSON живого прогона, повторно разбирает исходный файл и проверяет адреса цитат. Без файла рецензирования доступны паспорт с затратами, покрытие и доля восстановленных ссылок подтверждённых находок. Отсутствующее измерение и отношение с нулевым знаменателем обозначаются `null`.

Рецензенты сопоставляют подтверждённый дефект по сценарию, заявленному нарушению и доказательствам. Одно соответствие даёт один TP, дубликаты и несопоставленные подтверждённые находки входят в знаменатель precision, пропущенные эталонные дефекты дают FN. Полнота извлечения считается по уникальным покрытым эталонным правилам. Для false-positive rate отмечаются валидные сценарии, получившие хотя бы одну ложную тревогу. Для каждого вопроса рецензенты согласуют четыре оценки по порядку: конкретное решение, подходящий владелец, существенные последствия выбора, проверяемая правка. Первичные оценки и разногласия следует сохранять вместе с согласованным файлом. Схема входа доступна через `Review.model_json_schema()` в `eval_samples.evaluate`. Имена рецензентов заполняются по факту.
